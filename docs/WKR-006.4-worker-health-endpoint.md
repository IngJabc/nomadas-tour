# WKR-006.4 — Worker Health Endpoint

**Tipo:** Implementación (deploy / hosting)  
**Fecha:** 2026-08-07  
**Estado:** Implemented  
**Referencias:** [WKR-006.1](WKR-006.1-worker-observability-implementation.md), [ROADMAP](ROADMAP.md)

---

## Objetivo

Permitir ejecutar `nomadas-outbox-relay` en plataformas free que **exigen un puerto HTTP abierto** (p. ej. Render Free Web Service), sin Background Workers.

El proceso sigue siendo un worker de outbox; el HTTP solo expone liveness.

---

## Arquitectura

```text
runner.ts
  ├─ init observability (Sentry opcional)
  ├─ health server (Node http)  ← WKR-006.4
  ├─ heartbeat
  ├─ outbox relay + recovery scheduler
  └─ graceful shutdown (health → abort relay → flush Sentry)
```

Sin Express. Sin queries a Supabase en `/healthz`. Sin cambios a outbox/relay semantics.

---

## Endpoint

`GET /healthz`

```json
{
  "status": "ok",
  "service": "nomadas-outbox-relay",
  "worker_version": "1.0.0",
  "uptime_seconds": 123,
  "pid": 1234
}
```

- **200** si el proceso está vivo.
- No depende de DB / Resend / cola.

---

## Variable de entorno

| Variable | Default | Uso |
|----------|---------|-----|
| `WORKER_HEALTH_PORT` | `3002` | Puerto del health server |

### Render Free (Web Service)

Render inyecta `PORT`. Configurar:

```bash
WORKER_HEALTH_PORT=<mismo valor que PORT de Render>
```

o fijar el puerto del servicio a `3002` y usar el default.

Start command (tras build):

```bash
npm run worker:start
```

Health check path en el dashboard: `/healthz`.

---

## Deploy ideal vs workaround

| Modo | Cuándo | Notas |
|------|--------|-------|
| **Background Worker** | Plan que lo permita | Ideal: sin HTTP; solo logs/heartbeat |
| **Web Service + `/healthz`** | Render Free / similares | Workaround: puerto abierto + mismo proceso worker |
