# WKR-006.1 — Worker Observability Implementation

**Tipo:** Implementación  
**Fecha:** 2026-08-05  
**Estado:** Implemented  
**Referencias:** [WKR-006 foundation](WKR-006-worker-observability-foundation.md), [WKR-005](WKR-005-email-worker-implementation.md), [ROADMAP](ROADMAP.md)

---

## Objetivo

Observabilidad operativa básica del worker actual (`reservation.created.v1`) **sin** infraestructura externa (sin Sentry/Prometheus en este ticket).

---

## Cambios realizados

1. **Logger estructurado** (`backend/src/workers/observability/logger.ts`) — JSON por línea, scrub anti-PII.
2. **Métricas in-memory** — counters + `last_success_at` / `last_error_at` / duración.
3. **Heartbeat enriquecido** — `uptime_seconds`, `process_id`, `worker_version`, snapshot de métricas.
4. **Stuck recovery periódico** — RPC `recover_stuck_outbox_events` (migración 051) con intervalo propio `OUTBOX_RECOVERY_INTERVAL_MS`.
5. **Errores no controlados** — `uncaughtException` / `unhandledRejection` → log estructurado + shutdown + `exit(1)`.
6. **Tests** — logger, metrics, heartbeat, recovery scheduler, relay observability.

**No cambiado:** ADR-001, reservas, RPC, RLS, contratos de eventos, nuevos workers.

---

## Arquitectura

```text
npm run worker → runner.ts
  ├─ logger / metrics / heartbeat / recoveryScheduler
  ├─ uncaughtException / unhandledRejection handlers
  └─ runOutboxRelayLoop
       ├─ onLoopTick → heartbeat.maybeEmit
       ├─ recoverStuck (gated by recoveryScheduler)
       │    └─ recover_stuck_outbox_events RPC
       ├─ claim_outbox_events
       └─ processClaimedEvent → handler → mark + metrics + logs
```

## Eventos de logging

| Evento | Cuándo |
|--------|--------|
| `worker_started` | Boot |
| `worker_heartbeat` | Cada `OUTBOX_HEARTBEAT_MS` (+ boot forzado) |
| `outbox_claimed` | Claim con N>0 |
| `outbox_processing_started` | Antes del handler |
| `outbox_completed` | Mark completed |
| `outbox_requeued` | Requeue / backoff |
| `outbox_failed` | Mark failed |
| `outbox_recovery_completed` | Recovery devolvió ≥1 fila (`recovered_count`) |
| `handler_error` | Excepción del handler |
| `worker_uncaught_exception` / `worker_unhandled_rejection` | Fallos de proceso |
| `worker_shutdown` / `worker_stopped` / `worker_fatal` | Lifecycle |

Campos de correlación cuando aplica: `event_id`, `event_type`, `event_version`, `aggregate_id`, `tenant_id` / `agency_id`, `handler`, `duration_ms`, `status`.

Alias: el log de recovery incluye `event_alias: "outbox_recovered_stuck"` y `recovered` además de `recovered_count`.

| Métrica | Descripción |
|---------|-------------|
| `events_processed_total` | Completados (incluye skips) |
| `events_failed_total` | Mark failed |
| `events_retried_total` | Requeues |
| `events_skipped_total` | `already_sent` / `skipped_no_email` |
| `current_processing_count` | En vuelo en este proceso |
| `last_processing_duration_ms` | Última duración |

| `last_error_at` | ISO del último failed / uncaught / handler_error |

## Stuck recovery

| Env | Default | Rol |
|-----|---------|-----|
| `OUTBOX_STALE_PROCESSING_MS` | `300000` | Edad mínima en `processing` |
| `OUTBOX_STALE_RECOVERY_LIMIT` | `50` | Máx filas por ciclo |
| `OUTBOX_RECOVERY_INTERVAL_MS` | `60000` | Frecuencia (separada de `OUTBOX_POLL_MS`) |

RPC: `recover_stuck_outbox_events` (SKIP LOCKED). Log: `outbox_recovery_completed` con `recovered_count`.

## Health operacional

**HTTP liveness (WKR-006.4):** `GET /healthz` en `WORKER_HEALTH_PORT` (default `3002`).
Solo proceso vivo — sin DB. Ver [`WKR-006.4-worker-health-endpoint.md`](WKR-006.4-worker-health-endpoint.md).

Señales ops adicionales (logs / SQL):

```text
worker health = {
  alive:              GET /healthz 200  OR  worker_heartbeat reciente
  last_success_at:    metrics.last_success_at
  pending_ready:      SQL COUNT pending WHERE available_at <= now()
  failed_total:       SQL COUNT failed  (o metrics.events_failed_total)
  stuck_processing:   SQL COUNT processing WHERE updated_at stale
}
```

## Decisiones técnicas

| Decisión | Elección |
|----------|----------|
| Transporte de logs | stdout JSON |
| Heartbeat | logs (no HTTP, no tabla) |
| Recovery vs poll | intervalos separados |
| Métricas | in-memory proceso |
| Uncaught | log + exit(1), no tragar errores |
| PII | scrub en logger |
