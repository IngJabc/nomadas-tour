### 1.4 Toggle actual

`toggleBoarding` es una secuencia no transaccional:

```text

```

- `FOR UPDATE`
- RPC `boarding_toggle`
- campo `changed`
- idempotencia explícita

Bajo concurrencia puede sobrescribir `boarded_at` y duplicar `boarding_logs`.

### 1.5 Generación de QR

Fuente autoritativa: RPC `create_agency_reservation`
(`supabase/migrations/014_agency_reservation_function.sql:86-91`):

```sql
v_reservation_id := gen_random_uuid();
v_qr_code := 'NT-' || UPPER(COALESCE(v_destination, '')) || '-'
          || UPPER(REPLACE(v_reservation_id::TEXT, '-', ''));
```

Formato:

```text
NT-{DESTINATION}-{UUID32}
```

Ejemplo:

```text
NT-LA OLLA-6BBD52E983AB495493EAEE20466C18A2
```

Separación conceptual:

```text
prefijo:   NT-LA OLLA-
serial:    6BBD52E9
restante:  83AB495493EAEE20466C18A2
```

Conclusión de `ticket_code`:

| Pregunta | Respuesta |
|----------|-----------|
| ¿Existe columna `ticket_code`? | No |
| ¿Existe identificador estable? | Sí: `reservations.id` |
| ¿El QR contiene el UUID? | Sí, sin guiones |
| ¿Puede backfillearse? | Sí, con `UPPER(LEFT(REPLACE(id::text,'-',''),8))` |
| ¿Es único por sí solo? | No garantizado (32 bits) |
| ¿Hay que regenerar QR? | No |

La UI ya muestra códigos cortos inconsistentes:

- tickets/emails: `reservation_id.slice(0, 8)`
- scanner: `qr_code.split('-').pop()?.slice(0, 8)`

El backfill y la generación deben usar el UUID, no el parseo del QR.

## 4. Migraciones necesarias

### M1 — `ticket_code`

```text
ADD reservations.ticket_code TEXT NULL
backfill desde UUID
CHECK ^[0-9A-F]{8}$
UNIQUE
NOT NULL (tras validación)
UPDATE create_agency_reservation para generar y retornar ticket_code
```

Estrategia de colisiones:

1. candidato = primeros 8 hex del UUID;
2. precheck de duplicados en backfill;
3. resolver colisiones con código alternativo único;
4. en altas futuras: insert con retry ante `unique_violation`.

### M2 — `boarding_logs`

Agregar:

```text
trip_id
reservation_agency_id
state_before
state_after
```

Backfill:

- `trip_id` y `reservation_agency_id` por join a `reservations` (seguro);
- `state_before/after` nullable; NULL en históricos no demostrables.

### M3 — `boarding_attempts`

Crear tabla de intentos:

```text
lookup | board | unboard
outcomes: success | no_change | denied | not_found | error
credential_hash = sha256(input normalizado)
sin QR/código en claro
```

Pendiente operativo a cerrar en P1:

- retención;
- limpieza;
- índices finales.

### M4 — `boarding_toggle()`

Firma:

```sql
boarding_toggle(
  p_passenger_id UUID,
  p_boarded BOOLEAN,
  p_actor_user_id UUID,
  p_operator_agency_id UUID
)
```

Propiedades:

```sql
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
```

Permisos:

```sql
REVOKE EXECUTE FROM PUBLIC;
REVOKE EXECUTE FROM anon;
REVOKE EXECUTE FROM authenticated;
GRANT EXECUTE TO service_role;
```

Responsabilidades:

1. lock reserva → pasajero;
2. validar actor, agencia, viaje, `trip_agencies`, estados;
3. comparar estado actual vs solicitado;
4. actualizar solo si hay transición;
5. recalcular `reservations.status`;
6. insertar `boarding_logs` solo si `changed=true`;
7. retornar resultado con `changed`.

No usa `user_metadata`. No confía en el frontend para autorización.

## 6. Riesgos detectados antes de comenzar

| Riesgo | Severidad | Control antes/durante P1–P2 |
|--------|-----------|-----------------------------|
| Colisión de `ticket_code` (32 bits) | Media | Precheck SQL + UNIQUE + retry |
| Parsear código desde `qr_code.split('-')` | Media | Derivar siempre desde `reservations.id` |
| Consumidor HTTP externo de rutas legacy | Media | Revisar access logs antes del retiro |
| Deploy backend antes de RPC | Alta | Gate de deploy DB-first |
| `SECURITY DEFINER` mal grantado | Alta | REVOKE público; test de grants |
| Deadlock reserva/pasajero | Media | Orden fijo de locks; test concurrente |
| Históricos sin `state_before/after` | Baja | Nullable; no fabricar estados |
| Cleanup ciego de `seats.blocked` | Media | Preflight SQL; no cleanup sin evidencia |
| Crecimiento de `boarding_attempts` | Media | Definir retención en el PR de M3 |
| Lookup exacto aún enumerable por fuerza bruta | Baja-Media | Rate limiting + attempts + monitoreo |
| Scanner UX rota si se elimina fragmento sin guía | Media | Actualizar copy a “código de 8” o “QR completo” |

### Observaciones abiertas que no bloquean el diseño

Deben cerrarse como primer trabajo de P0/P1, no como rediseño:

1. Ejecutar preflight SQL de AUD-020.2 en DB viva.

3. Definir retención mínima de `boarding_attempts`.
4. Confirmar ausencia de tráfico externo a rutas legacy.
