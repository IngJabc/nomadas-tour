### 2.1 Boarding guard (existente)

Cubierto:

**Permitido**

- agencia asignada + viaje activo + salida pasada
- `departure_time` exactamente ahora
- salida en el pasado

**Rechazado**

- viaje futuro
- viaje cancelado
- viaje completado
- viaje no encontrado
- agencia no asignada

### 2.2 `lookupPassengerByQR` (nuevo)

Cubierto:

- encuentra coincidencia por fragmento
- devuelve pasajero y contrato actual
- vacía resultados sin match
- filtra agencias no asignadas al viaje

**Caracterización explícita del comportamiento actual (NO contrato final):**

- acepta fragmentos;
- usa `.ilike('qr_code', '%…%')`;
- el DTO incluye `booker_document`, `passenger.document` y `qr_code`.

### 2.3 `toggleBoarding` (nuevo)

Cubierto:

- board pasajero → log `board` + status agregado;
- unboard pasajero → log `unboard` + status `confirmed`;
- status `partial` con pasajeros mixtos;
- rechazo de pasajero cancelado;
- escritura de `boarding_logs` con actor/agencia/pasajero.

**Caracterización explícita del comportamiento actual (NO contrato final):**

- no existe campo `changed`;
- no existe RPC `boarding_toggle`;
- no hay transacción/`FOR UPDATE`;
- un segundo board sobre pasajero ya abordado **sí inserta** un log.

### 2.4 Scanner frontend (nuevo)

Cubierto:

- `app/agency/scan/page.tsx` llama `lookupPassengerByQR` y `toggleBoarding`;
- `lib/api.ts` expone el cliente Sprint 13;
- 0 callers internos de `agencyApi.boardPassenger`;
- 0 clientes frontend de `/agency/scanner/lookup` o `/agency/scanner/board`;
- la definición legacy `/agency/reservations/board` sigue en `lib/api.ts` (sin uso).

## 3. Comportamiento congelado

```text
Scanner
  → GET /agency/boarding/:qrCode
  → lookupPassengerByQR (ILIKE parcial)
  → DTO amplio (incluye PII)

Scanner
  → PATCH /agency/boarding/:passengerId
  → toggleBoarding (multi-query)
  → boarding_logs siempre insertado
  → respuesta sin `changed`
```

Legacy HTTP todavía montado, sin consumidores frontend internos.
