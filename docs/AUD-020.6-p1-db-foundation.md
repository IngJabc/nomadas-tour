## 3. SQL aplicado (resumen)

### 3.1 M1 — `ticket_code`

```sql
ALTER TABLE public.reservations
  ADD COLUMN IF NOT EXISTS ticket_code CHAR(8);

UPDATE public.reservations
SET ticket_code = UPPER(LEFT(REPLACE(id::text, '-', ''), 8))
WHERE ticket_code IS NULL;

-- Precheck: RAISE EXCEPTION si hay grupos duplicados (sin remap silencioso)
-- CHECK: ticket_code IS NULL OR ticket_code::text ~ '^[A-F0-9]{8}$'
-- UNIQUE(ticket_code)
```

Decisiones respetadas:

- fuente = `reservations.id` (UUID), **no** `qr_code`;
- columna permanece **nullable**;
- colisiones → abortan la migración y deben documentarse/resolverse manualmente;
- no se toca `create_agency_reservation`.

### 3.2 M2 — `boarding_logs`

Columnas nuevas:

| Columna | Backfill |
|--------|----------|
| `trip_id` | `boarding_logs → reservations.trip_id` |
| `reservation_agency_id` | `boarding_logs → reservations.agency_id` |
| `state_before` | **NULL** en históricos |
| `state_after` | **NULL** en históricos |

Índices: `trip_id`, `reservation_agency_id`.

FK a `trips` / `agencies` solo si no hay huérfanos tras el backfill; si hay huérfanos, se emite `NOTICE` y se omiten las FK.

### 3.3 M3 — `boarding_attempts`

Campos mínimos según brief P1:

- `id`, `created_at`
- `actor_user_id`, `operator_agency_id`
- `trip_id`, `reservation_id`, `reservation_passenger_id` (nullable)
- `operation` ∈ `lookup|board|unboard`
- `outcome` ∈ `success|no_change|denied|not_found|error`
- `failure_code`, `credential_hash` (nullable)

Restricciones operativas:

- no QR / ticket_code / documentos / payload en claro;
- **no** Realtime;
- RLS habilitado **sin** policies de cliente (deny-by-default);
- `REVOKE` a `PUBLIC` / `anon` / `authenticated`;
- `GRANT SELECT, INSERT` a `service_role`;
- retención objetivo documentada: **90 días** (job de purga pendiente ops/P2).

### 3.4 M4 — `boarding_toggle`

Firma:

```sql
public.boarding_toggle(
  p_passenger_id UUID,
  p_boarded BOOLEAN,
  p_actor_user_id UUID,
  p_operator_agency_id UUID
) RETURNS JSONB
```

Propiedades:

```sql
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
OWNER TO postgres  -- si el rol existe
```

Flujo:

1. resolver reserva del pasajero;
2. `FOR UPDATE` reserva → pasajero;
3. validar actor, membresía en agencia operadora, viaje, `trip_agencies`, reserva y pasajero;
4. comparar `boarded` actual vs `p_boarded`;
5. actualizar solo si cambia;
6. recalcular `reservations.status`;
7. insertar `boarding_logs` solo si `changed=true` (incluye columnas nuevas);
8. retornar JSON con `changed`.

Grants:

```sql
REVOKE EXECUTE ... FROM PUBLIC;
REVOKE EXECUTE ... FROM anon;
REVOKE EXECUTE ... FROM authenticated;
GRANT EXECUTE ... TO service_role;
```

No usa `auth.uid()`, JWT ni `user_metadata` como fuente de autorización.

## 5. Riesgos encontrados

| Riesgo | Severidad | Estado / control |
|--------|-----------|------------------|
| Colisión de `ticket_code` en backfill (32 bits) | Media | Migración aborta con EXCEPTION + sample; no remap silencioso |
| `ticket_code` sigue nullable + creación aún no lo genera | Media | Intencional; P2 debe actualizar `create_agency_reservation` + retry |
| Históricos sin `state_before/after` | Baja | Esperado; solo filas nuevas vía RPC |
| FK de `boarding_logs` omitidas si hay huérfanos | Media | NOTICE en migración; requiere inspección manual |
| RPC aún no llamada por backend | Baja | Correcto para P1; deploy DB antes de P2 |
| Crecimiento de `boarding_attempts` | Media | Retención 90d documentada; purga no implementada |
| Verificación RPC deny depende de fixtures vivos | Media | Script hace SKIP seguro; smoke manual recomendado |
| `CHAR(8)` vs `TEXT` | Baja | Pedido explícito; CHECK castea a `text` para el regex |
