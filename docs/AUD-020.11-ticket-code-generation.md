# AUD-020.11 — Complete ticket_code generation for new reservations

**Tipo:** Cierre de residual P1 / generación en creación  
**Fecha:** 2026-08-05  
**Estado:** Implemented  
**ADR-001:** Intacta (Accepted) — sin cambios  

---

## Problema encontrado

Tras aplicar la migración `043`, las reservas **históricas** tenían `ticket_code` (backfill desde `id`). Las reservas **nuevas** creadas por `create_agency_reservation` seguían insertando solo `qr_code`, dejando `ticket_code = NULL`.

El scanner de boarding hace lookup exacto por `ticket_code` (8 hex) o `qr_code` completo. Sin `ticket_code` en altas nuevas, el código corto del boleto no encontraba la reserva.

## Causa raíz

`043` documentó explícitamente: *Do NOT modify create_agency_reservation in this migration*. La generación en INSERT quedó pendiente. La función en `014` nunca escribió `ticket_code`.

## Cambio aplicado

Nueva migración (sin editar migraciones ya aplicadas):

`supabase/migrations/047_update_create_agency_reservation_ticket_code.sql`

- `CREATE OR REPLACE FUNCTION public.create_agency_reservation` — **misma firma**
- Mantiene `SECURITY DEFINER` + `SET search_path = public`
- Generación de `qr_code` **sin cambios**
- Tras `gen_random_uuid()`:

```sql
v_ticket_code :=
  UPPER(LEFT(REPLACE(v_reservation_id::text, '-', ''), 8));
```

- `INSERT INTO reservations (..., ticket_code, ...)`
- Retorno JSON additive: `{ reservation_id, qr_code, ticket_code }`
- Reafirma grants: `EXECUTE` solo `service_role` (postura 037)

No se modificó:

- flujo de boarding / `boarding_toggle`
- RLS / auth
- ADR-001
- columnas nuevas

## Migración 047

| Ítem | Valor |
|------|-------|
| Archivo | `047_update_create_agency_reservation_ticket_code.sql` |

Tras crear una reserva nueva, descomentar el bloque smoke del mismo archivo o correr:

```sql
SELECT
  id,
  ticket_code,
  qr_code,
  UPPER(LEFT(REPLACE(id::text, '-', ''), 8)) AS expected_ticket_code
FROM public.reservations
ORDER BY created_at DESC NULLS LAST
LIMIT 1;
```

Esperado: `ticket_code` NOT NULL, 8 chars, `^[A-F0-9]{8}$`, igual a `expected_ticket_code`.

Scanner: ticket corto y QR completo deben encontrar la reserva (reglas de autorización operativas sin cambios).

## Impacto en AUD-020

Cierra el residual documentado en AUD-020.6 / AUD-020.9: *nuevas reservas sin `ticket_code`*. El contrato de boarding (lookup exacto + envelope + RPC) no cambia; solo garantiza que el identificador corto exista desde la creación.

## Riesgos restantes

1. Reservas creadas **entre** aplicar `043` y aplicar `047` pueden seguir con `ticket_code` NULL — re-backfill puntual si hace falta (`UPDATE ... WHERE ticket_code IS NULL` con la misma fórmula).
2. Colisiones UNIQUE del prefijo de 8 hex siguen siendo teóricas (misma superficie que el backfill 043).
3. Firma live de creación + scanner en staging sigue siendo checklist operador.
